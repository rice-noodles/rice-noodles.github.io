WebSocket的基本概念以及在SpringBoot中的应用

发表于2025-08-26|更新于2025-08-26|Java
|浏览量:

基本特性

  1. 双向通信：平時的HTTP请求只可以由客户端发起，服务器端没法主动向客户端推送信息。WebSocket协议解决了这个问题，WebSocket是一种在单个TCP连接上进行全双工通信的协议，服务器可以主动向客户端推送数据，客户端也可以随时向服务器发送数据。
  2. 实时性强：因为WebSocket连接是持久的，数据可以立即从一方发送到另一方，无需建立新的连接开销。这使得通信非常及时，近乎实时。
  3. 低开销：与HTTP请求每次都需要携带完整的头部信息不同，WebSocket在建立连接后，数据传输的包非常小，头部开销极小，非常适合高频、小数据量的场景。

工作过程

  1. 握手过程：
    1. 客户端首先发送一个特殊的HTTP请求，头信息中包含Upgrade: websocket和Connection: Upgrade等字段，告诉服务器：“需要把协议升级成WebSocket”。
    2. 服务器如果支持WebSocket，会返回一个101 Switching Protocols的响应，表示：“同意升级协议”。
    3. 至此，HTTP握手完成，接下来的通信就不再使用HTTP协议，而是使用WebSocket协议进行双向数据传输。
  2. 数据传输：握手成功后，TCP/IP连接保持打开状态，客户端和服务器就可以通过这个连接自由地互相发送数据。
  3. 连接关闭：任何一方都可以发送一个关闭信号来优雅地终止连接。

与 HTTP 的对比

特性 WebSocket HTTP
通信方式 双向，服务器可主动推送 单向，必须是客户端先请求
连接状态 持久连接 非持久，请求-响应后通常关闭
开销 连接建立后，数据包头部开销很小 每次请求/响应都包含完整的头部信息
适用场景 实时应用（聊天、游戏、通知） 请求-响应模式（网页浏览、API调用）
协议 ws(非加密)或wss(加密，类似 HTTPS) http或https
